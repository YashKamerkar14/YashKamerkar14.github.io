Quick puzzle

Can you spot the bug?

This report gets slower every day the database grows. Click the line that's causing it.

order_report.py

It's an N+1 query. Line 2 fetches the orders in one query, then line 5 runs another query for every single order. 10,000 orders means 10,001 trips to the database.

The fix: load the customers in the same query

orders = db.query(Order).options(joinedload(Order.customer)).all()
rows = [(o.id, o.customer.name, o.total) for o in orders]

Not a made-up example. At Dell, I rewrote 3 N+1 query patterns and added composite indexes, cutting average response time from 2.1 s to 340 ms.
